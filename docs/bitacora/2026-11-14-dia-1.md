## Conceptos aprendidos

- **`engines` en `package.json`:** cada paquete declara qué versiones de Node soporta. Wrangler, OpenSpec 2 y vitest exigen Node ≥ 22.12; con Node 20 fallan. fnm permite tener varias versiones y cambiar según el `.node-version` de cada carpeta, y los paquetes globales quedan separados por versión.
- **`.gitattributes` frente a `core.autocrlf`:** `autocrlf` depende de la configuración de cada máquina; `.gitattributes` viaja con el repo y se aplica igual en Windows y en el CI de Linux. Los binarios se marcan para que Git nunca les cambie los saltos de línea.
- **Primer commit intacto:** permite mostrar con `git diff` exactamente qué se cambió del diseño original y por qué.
- **OpenSpec 2:** las skills quedan en `.agents/skills/` (convención compartida por varios agentes, incluido Antigravity) con enlaces desde `.claude/skills/`; los comandos `/opsx:*` del curso pasan a ser `/openspec-*`.
- **Spec primero, también para mejorar:** las mejoras se escribieron en los specs (requisito + escenarios WHEN/THEN), luego en el diseño (decisión + alternativa descartada) y en las tareas (con su verificación), antes de cualquier código.
- **Defensa en profundidad con triggers:** las reglas de dinero y notas se validan en la API **y** en la base (`RAISE(ABORT, 'CODIGO')`), como en Oracle con `RAISE_APPLICATION_ERROR`. Una migración solo se puede editar mientras no se haya aplicado en ninguna base.
- **Calcular en vez de guardar:** la mora y la marca de entrega tardía se calculan al vuelo para que nunca queden desactualizadas.
- **Sesiones JWT revocables:** un JWT puro no se puede invalidar antes de que venza; con `sesion_version` en la base, restablecer la contraseña o desactivar a un usuario cierra sus sesiones al instante.
- **Binding en lugar de cadena de conexión:** Cloudflare le entrega la base al Worker como un objeto (`env.DB`). No hay usuario, contraseña ni URL que se puedan filtrar.
- **Infraestructura como código:** `wrangler.jsonc` describe el Worker, sus recursos y sus variables, versionado en git.
- **`--local` frente a `--remote`:** es el mismo comando sobre la copia del PC o sobre Cloudflare. Antes de ejecutar algo que modifique datos, hay que buscar el `--remote`.
- **D1 no es SQLite completo:** bloquea funciones como `sqlite_version()`.
- **UTC frente a Colombia:** `date('now')` en D1 ya decía 15 de noviembre mientras en Colombia era 14. Por eso la mora se calcula en el código con America/Bogota (D6).
- **Las migraciones son historia:** D1 registra en `d1_migrations` qué archivos aplicó. Se aplican primero en local y después en remoto, y una vez aplicadas no se editan.
- **Seed determinista con fecha de referencia:** el mismo seed sirve toda la semana. Con SQL se verificó que los estados de cartera no cambian del 6 al 29 de noviembre, y esa verificación corrigió un cálculo hecho a mano.
- **La región de los datos es una decisión legal:** D1 en EE. UU. es una transferencia internacional según la Ley 1581, y debe ir en el aviso de privacidad.
- **Revisar si un paquete está obsoleto antes de instalarlo** (`npm view <paquete> deprecated`): el kit nombraba `@cloudflare/vitest-pool-workers`, que Cloudflare había renombrado.
- **Un solo `workerd`:** Wrangler, `vite-plugin` y `vitest-plugin` se actualizan juntos para que desarrollo, pruebas y producción usen el mismo runtime.
- **Una prueba que nunca falló no prueba nada:** se rompió el endpoint a propósito para confirmar que la prueba lo detecta.
- **`npm audit` se interpreta:** `audit fix --force` habría *bajado* `shadcn` a 1.0.0 y `typescript-eslint` a 8.36.
- **Seguridad del CI:**
  - Las actions se fijan por SHA, no por etiqueta.
  - Los secretos solo se usan en un push a `main`, nunca en pull requests.
  - El token de Cloudflare es de cuenta, con permisos mínimos y fecha de vencimiento.
- **La aprobación humana de las specs es el corazón de OpenSpec:** aprobar una lista de mejoras no es aprobar el documento.

## Problemas y cómo se resolvieron

| Problema | Causa | Solución |
|---|---|---|
| Wrangler, OpenSpec 2 y vitest no corrían | Node 20 en el PATH del sistema | fnm con Node 24 y `fnm env --use-on-cd` en el perfil de PowerShell |
| Git advertía que convertiría `placeholder.pdf` | `core.autocrlf=true` trataba el PDF como texto y lo habría corrompido | `.gitattributes` con `*.pdf binary` |
| La propuesta prometía recuperación por correo y el diseño no | Alcance comercial y técnico desalineados | Se mantiene el restablecimiento por el administrador; el correo pasa a una fase posterior |
| El plan Free de Workers da 10 ms de CPU por petición | PBKDF2 con 100.000 iteraciones podría superarlo | Tarea 1.8 para medirlo con el Worker desplegado |
| TypeScript 7 rompía el lint | `typescript-eslint` aún no lo soporta | TypeScript `~6.0` |
| Dos copias de `workerd` | Wrangler 4.162 en la raíz y 4.160 dentro del plugin de Vite | Wrangler fijo en 4.160.0 |
| npm 11 no ejecutaba los scripts de instalación | Defensa contra ataques a la cadena de suministro | Se revisaron `workerd` y `esbuild` y se aprobaron con `allowScripts` |
| El campo del subdominio no aceptaba puntos | Se escribió la URL completa | Solo va la etiqueta `creativebycode`; `senda` lo pone el nombre del Worker |
| D1 rechazó `sqlite_version()` | D1 restringe algunas funciones de SQLite | Verificar con una consulta simple |
| Wrangler propuso los bindings `senda_db` y `senda_archivos` | Nombres automáticos | IDs copiados a mano a los bindings `DB` y `ARCHIVOS_KV` |
| `@cloudflare/vitest-pool-workers` estaba obsoleto | Cloudflare lo renombró en octubre | `@cloudflare/vitest-plugin` 1.7.0, que trae el mismo Wrangler que el plugin de Vite |
| CLAUDE.md anunciaba `db:migrate` y `db:seed`, pero no existían | Descuido en las tareas 1.3 y 1.4 | Scripts agregados y probados (solo local) |
| Se empezó a implementar sin que Aymer leyera el proposal y las specs completos | Se aprobaron mejoras puntuales, no los documentos | Sesión de revisión del MVP antes del grupo 2. Lo hecho hasta ahora es solo infraestructura |
