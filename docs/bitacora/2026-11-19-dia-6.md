## Conceptos aprendidos

- **Evaluar un modelo es medir, no opinar:** un conjunto fijo de preguntas con la respuesta esperada da un número comparable entre modelos y entre cambios.
- **Calificar con reglas o con un modelo juez:** las reglas dan siempre el mismo resultado, no gastan cuota y se explican. Un modelo juez entiende más matices, pero varía entre corridas y cuesta.
- **No mover la meta:** si se corrige el calificador, el reporte original se conserva y las mismas respuestas se vuelven a calificar. Así se ve qué cambió y por qué.
- **El costo de un modelo se mide en tokens:** cada paso del agente envía otra vez todo el contexto. Con el precio por modelo se calcula cuántas preguntas aguanta la Fundación.
- **Doble de prueba o modo simulado:** en Vitest se reemplaza el binding; en el E2E, que prueba el build real, la simulación tiene que ir en el build. Por eso necesita un candado que no dependa de la configuración.
- **Configuración del build o de la ejecución:** `vite preview` usa las variables con las que se hizo el build. De `.dev.vars` solo toma los secretos declarados.
- **Verificar antes de corregir:** una captura de página completa puede mostrar mal los elementos fijos (`sticky`). Se confirma en la pantalla real.
- **Archivar en OpenSpec:** las specs delta describen lo que un cambio agrega, y al archivar se integran en las specs principales, que describen lo que el producto es.

## Problemas y cómo se resolvieron

| Problema | Causa | Solución |
|---|---|---|
| Parecía que el push estaba hecho y no lo estaba | El texto pegado era el de un push anterior | Confirmar con `git status -sb` y `git ls-remote` antes de dar un push por hecho |
| El lint encontró espacios invisibles en una expresión regular | Otra vez los escapes `\u` escritos por la herramienta se volvieron el carácter real | Escapes construidos con Node y, para las tildes, la clase `\p{M}`, que no usa escapes |
| El código enviado al MCP falló con "Unexpected token" | El archivo terminaba en `;` y el MCP lo evalúa como una expresión | Quitar el punto y coma final |
| El MCP no podía leer las capturas para armar las hojas de contacto | Su código no puede importar módulos de Node | Un servidor estático mínimo en el puerto 8765 |
| Fue denegado vaciar los documentos de la base local para probar el camino del CI | Eran datos locales de Aymer, aunque hubiera respaldo | Una copia aparte del repositorio (`git worktree`) con su propia base vacía |
| No se podía borrar esa copia ("Filename too long") | Rutas muy largas dentro de `.wrangler` | Se quitó primero el enlace a `node_modules` con `rmdir`, sin tocar las dependencias; la carpeta quedó en el directorio temporal |
| El lint revisaba la salida del MCP | `.playwright-mcp/` no se versiona, pero ESLint no lee el `.gitignore` | ESLint la ignora |
| Un comando de Node con comillas simples dentro de Bash se rompió | Las comillas simples cerraban la cadena de Bash | Usar la herramienta de edición para esos cambios |
