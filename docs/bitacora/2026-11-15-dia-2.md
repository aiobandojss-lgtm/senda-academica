## Conceptos aprendidos

- **API token de cuenta con permisos mínimos y fecha de vencimiento.** Los secretos los carga la persona y nunca pasan por el chat ni por el repositorio.
- **Medir antes de decidir:** el `cpuTime` de `wrangler tail` mostró el costo real. La decisión quedó en un ADR, con sus alternativas y un plan B.
- **Aprobar specs con supuestos es válido** si queda escrito qué se supuso y cuándo se revalida.
- **Guardar contraseñas:**
  - Sal aleatoria.
  - Las iteraciones viajan dentro del hash, lo que permite migrar.
  - NFKC, porque la "ñ" puede llegar en dos formas según el teclado.
  - Comparación en tiempo constante.
- **El azar también tiene sesgo:** `byte % 56` favorece unos caracteres sobre otros; el muestreo con rechazo lo corrige.
- **TDD de verdad:**
  - El rojo debe fallar por la razón correcta.
  - Una prueba que pasa en vacío no protege nada.
  - Las mutaciones (dañar el código a propósito) demuestran que las pruebas detectan errores reales.
- **Cookie `__Host-` con HttpOnly y SameSite=Lax:** el navegador guarda la sesión, ningún JavaScript puede leerla y otros sitios no pueden usarla para enviar peticiones a nombre del usuario.
- **No revelar si un documento existe:** mismo mensaje, mismo código y mismo tiempo. "Cuenta inactiva" solo se dice con la contraseña correcta.
- **JWT con algoritmo explícito:** `verify` exige HS256. Un token firmado con otra clave se rechaza aunque diga ser de un administrador.
- **Fallar rápido:** con `secrets.required`, el deploy falla si falta un secreto en vez de publicar un login roto.
- **Condiciones de carrera ("verificar y luego actuar"):** entre contar y actuar no puede quedar un hueco. Un `batch` de D1 es una transacción, como `SELECT … FOR UPDATE` en Oracle.
- **Verificar lo que uno afirma:** un comentario sobre la prioridad de `.dev.vars` resultó falso. Una prueba de 5 líneas lo reveló antes del commit.
- **La IA del producto no necesita una API key externa:** Workers AI llega al Worker como binding (`env.AI`). Claude Code es la herramienta de desarrollo, no parte del producto.
- **Habeas Data y minimización:**
  - Se piden solo los datos necesarios.
  - El tipo de sangre es un dato sensible.
  - Guardar datos en EE. UU. es una transferencia internacional y debe ir en el aviso de privacidad.

## Problemas y cómo se resolvieron

| Problema | Causa | Solución |
|---|---|---|
| Las instrucciones para crear el token confundían | Demasiados pasos en un solo mensaje | Una pantalla a la vez, con captura |
| No aparecía el botón "Continue to summary" | En la interfaz actual se llama "Review token" | Corregido sobre la captura |
| Se bloqueó la escritura de un archivo con "secretos" en el nombre | Regla de permisos que protege esos archivos | El documento se llamó `despliegue.md`; la regla se respeta |
| `gh run list --commit` no devolvía nada | Con el SHA corto no encuentra el run | Usar el SHA completo o el ID del run |
| La prueba "sin caracteres ambiguos" pasaba con la función vacía | Pasaba en vacío | Exigir 10 caracteres válidos: `/^[^0Oo1lI]{10}$/` |
| Propuesta de bajar a 10.000 iteraciones | Riesgo de exceder la CPU del plan Free | Aymer decidió 100.000 y pagar Paid después del 20 (ADR-003) |
| El chequeo de tipos del CI podía romperse | `wrangler types` infería los secretos del `.dev.vars` local | `secrets.required` en `wrangler.jsonc` |
| Advertencia "Missing required secrets" en las pruebas | Wrangler revisa los secretos antes de que Vitest agregue la clave de prueba | Clave de prueba en `process.env` y en `miniflare.bindings` |
| La clave de prueba no tenía prioridad sobre `.dev.vars`, como decía el comentario | Si existe `.dev.vars`, Wrangler usa solo ese archivo | Verificado con una prueba temporal y corregido; la regla quedó en CLAUDE.md |
| El clasificador de permisos bloqueó `wrangler secret put` | Los secretos los carga Aymer (CLAUDE.md) | Aymer ejecutó el comando; se verificó con `wrangler secret list` |
| Advertencia de secreto faltante en el build del CI | `vite build` prepara `vite preview` y en el CI no hay `.dev.vars` | Es esperada; quedó documentada en `despliegue.md` |
| D14 permitía saltarse el límite con intentos simultáneos | Contar e insertar en pasos separados | Registro y conteo en un `batch` de D1 (decisión de Aymer) |
